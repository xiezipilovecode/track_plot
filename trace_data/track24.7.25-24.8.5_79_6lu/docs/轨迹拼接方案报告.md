## 一、数据概览与格式分析

### 1.1 文件命名规则

文件名格式：`{公里桩}+{偏移}TV{编号}_{年}-{月}-{日}-{时}-{分}-{秒}.txt`

示例：`K615+703TV023_2024-07-25-14-40-19.txt`

| 字段 | 说明 | 示例值 |
|------|------|--------|
| K615+703 | 公路公里桩号K615 + 偏移703m | 即公里标 615703m |
| TV023 | 摄像头编号 | 23号 |
| 2024-07-25-14-40-19 | 轨迹数据窗口起始时刻 | 2024年7月25日 14:40:19 |

### 1.2 六路摄像头配置（基于全量数据实际统计）

| 编号 | 摄像头ID | 公里桩位置 | 实际y坐标范围 (cm) | y跨度 |
|------|----------|-----------|-------------------|-------|
| CAM1 | TV023 | K615+703 | 61,571,000 – 61,583,500 | ~12,500 |
| CAM2 | TV024 | K615+833 | 61,585,000 – 61,592,800 | ~7,800 |
| CAM3 | TV025 | K615+963 | 61,597,700 – 61,613,800 | ~16,100 |
| CAM4 | TV026 | K616+093 | 61,610,800 – 61,630,700 | ~19,900 |
| CAM5 | TV027 | K616+223 | 61,623,900 – 61,645,500 | ~21,600 |
| CAM6 | TV028 | K616+323 | 61,633,500 – 61,651,300 | ~17,800 |

> **隧道总覆盖长度**: 约620米（K615+703 至 K616+323）。每个摄像头的有效检测范围远大于最初估计（120m-250m不等），相邻摄像头之间存在显著的重叠区域。

> **重要说明**: 上表中的"实际y坐标范围"是基于各摄像头第一个时间窗口（2024-07-25 14:40-15:10）的前30行数据统计的近似范围。实际范围可能因不同时间段的车流分布而有所扩展。更精确的范围应在实现阶段通过完整遍历所有文件来动态计算。

每个摄像头文件按约30分钟的时间窗口切分，总共 **3,186个文件**（每路约531个文件）。每天产生48个时间窗口（24h ÷ 0.5h），11天共约528个窗口/摄像头，与文件数一致。文件时间覆盖完整，无明显缺失。

### 1.3 轨迹数据格式

每个 `.txt` 文件的每一行对应一条完整的车辆轨迹。数据以空格分隔，格式如下：

```
时间戳 x坐标 y坐标 瞬时速度 加速度 类型 [时间戳 x坐标 y坐标 瞬时速度 加速度 类型]...
```

每个轨迹节点由 **6个字段** 组成：

| 序号 | 字段名称 | 数据类型 | 说明 | 示例值 |
|------|----------|----------|------|--------|
| 1 | 时间戳 (timestamp) | Long整数 | Unix毫秒时间戳 | `1721889619088` |
| 2 | x坐标 (x) | Float | 图像/像素x坐标 | `612.91` |
| 3 | y坐标 (y) | Float | **世界坐标y值**（统一坐标系） | `61579708.47` |
| 4 | 瞬时速度 (speed) | Float | 瞬时速度（km/h） | `0.000000` 或 `null` |
| 5 | 加速度 (acceleration) | Float | 加速度 | `null` 或数值 |
| 6 | 类型 (type) | 字符串 | 车辆类型 | `car`, `truck`, `van`, `bus`, `pika` |

> **关键发现**：**y坐标是世界统一坐标系**，不同摄像头间的y坐标可以直接比较和拼接。例如：TV023的y坐标在6157xxxx范围，TV024在6158xxxx范围，y坐标值随公里桩递增而单调递增。

**单节点轨迹示例**（只有1个跟踪点）：
```
1721889619088 612.91 61579708.47 0.000000 null car
```

**多节点轨迹示例**（有多个跟踪点，6个字段一组循环）：
```
1721889619151 586.36 61580935.63 0.000000 null car 1721889619234 608.72 61580789.11 10.272559 -10.272559 car 1721889619638 593.84 61581423.48 43.938865 -33.666306 car
```

### 1.4 坐标系统分析

**y坐标（世界坐标）** 采用统一的全局坐标系：

- y坐标值范围从约 61,570,000 到 61,651,300
- **y坐标单位约为厘米（cm）**：通过速度（km/h）反算验证——位置差 ÷ 时间差 ÷ 速度换算得到的 y 坐标差与速度字段大致吻合。相邻摄像头间距130m对应y差值约13000单位（=130×100cm），进一步证实了cm单位的推断
- 增量方向与隧道里程递增方向一致
- 不同摄像头间的y坐标存在**显著重叠**（如TV025尾端y≈61613800与TV026前端y≈61610800有约3000cm重叠）

**x坐标（像素坐标）** 表示在单摄像头图像中的水平位置，单位约为像素。不同摄像头间的x坐标不可直接比较。

**⚠️ 异常坐标点 (0,0)**：数据中存在(x=0, y=0)的异常坐标点，这是跟踪丢失或短暂遮挡的标志。在某些摄像头（如TV023）的文件中，高达约**48%**的轨迹包含至少一个(0,0)点。
**处理策略**：在解析时将(0,0)点标记为 `invalid`，在匹配计算轨迹特征时跳过这些点，使用最近的有效节点作为替代。若轨迹中所有节点均为(0,0)，整条轨迹标记为无效并排除。

### 1.5 时间同步特性

所有文件的时间戳均为 **Unix毫秒时间戳**，六路摄像头的时钟已经同步。这允许利用时间戳进行直接的时空关联匹配。

### 1.6 数据质量注意事项

以下是从实际数据中发现的、对拼接算法设计有重要影响的特征：

#### 1.6.1 轨迹内车辆类型不恒定

同一轨迹的不同节点可能被标注为不同类型。例如：
```
car → pika → car → truck → truck  （TV025，单条轨迹内5种类型变化）
car → van → van → truck → car → car → truck  （TV028）
```

这对匹配算法有直接影响：不能简单取首/末节点的类型做比较，需要采用**多数投票**策略。

#### 1.6.2 罕见车辆类型 `motorbike`

数据中偶尔出现 `motorbike` 类型（如TV026 line 21），虽极为罕见，但解析器需容错处理。

#### 1.6.3 静止/振荡轨迹

后期摄像头（TV027、TV028）中存在大量静止车辆轨迹，y值在小范围内来回振荡，speed≈0。典型的如TV028中y值在61644260~61644391之间反复振荡的车辆。这些轨迹代表停在路侧的车辆（或固定物体），不应参与跨摄像头匹配。**处理策略**：通过y坐标标准差和平均速度检测静止轨迹，标记为"静止"类别，仅用于流量统计。

#### 1.6.4 异常加速度值

许多轨迹点的加速度绝对值达到50-100+，这在物理上不可行（普通乘用车最大加速度约3-5m/s²）。这些异常值来自跟踪噪声，在匹配和插值中应降低其权重或忽略。

## 二、轨迹拼接方法调研综述

### 2.1 方法分类

多摄像头轨迹拼接方法主要分为两大类：

#### 2.1.1 早期拼接（Early Connection / Image Stitching）
先将多路视频/图像拼接成全景影像，再从中提取完整轨迹。

- **适用条件**: 摄像头视场有较大重叠区域
- **优点**: 直观，可视化效果好
- **缺点**: 依赖精确的相机标定；对非重叠区域（盲区）效果差；计算量大

#### 2.1.2 晚期拼接（Late Connection / Trajectory Association）
先从各摄像头独立提取轨迹，再通过关联算法将轨迹片段拼接成完整轨迹。

- **适用条件**: 摄像头视场可以有重叠区、边界相接或无重叠（有盲区）
- **优点**: 不依赖相机标定；适用于非重叠摄像头环境；计算高效
- **缺点**: 需要对车辆进行跨摄像头匹配

> **本数据集推荐采用晚期拼接方法**，原因如下：
> 1. y坐标为统一世界坐标，无需进行图像级拼接
> 2. 摄像头间距130米，既存在重叠又存在盲区
> 3. 晚期拼接方法更灵活、计算效率更高

### 2.2 跨摄像头车辆匹配方法

| 方法 | 核心思想 | 优点 | 缺点 | 适用性 |
|------|----------|------|------|--------|
| **时空约束匹配** | 利用时间戳+空间位置的物理约束进行匹配 | 简单、无需图像特征 | 需要统一坐标和时间同步 | ⭐⭐⭐⭐⭐ |
| **匈牙利算法** | 将轨迹匹配转化为二分图最优分配问题 | 数学上全局最优 | 需要定义合理的代价函数 | ⭐⭐⭐⭐⭐ |
| **匈牙利+卡尔曼滤波** | 先预测轨迹位置，再进行匈牙利匹配 | 处理噪声和盲区 | 需要调参 | ⭐⭐⭐⭐ |
| **车辆重识别(ReID)** | 基于车辆外观特征匹配 | 不受位置约束 | 需要原始图像，隧道光照影响大 | ⭐⭐ |
| **轨迹匹配代价最小化** | 最小化轨迹间的匹配代价来拼接 | 适用于无重叠场景 | 需要足够的观测数据 | ⭐⭐⭐⭐ |

## 三、本数据集的拼接策略方案

### 3.0 预备步骤：同一摄像头跨文件拼接

在跨摄像头匹配之前，需要先处理同一摄像头内的轨迹片段断裂问题。一辆车可能在相邻的两个30分钟时间窗口（如14:40和15:10）中各有一段轨迹，需要先将它们识别为同一辆车。

**策略**：对每个摄像头的数据，按时间顺序遍历相邻文件窗口，对窗口边界附近的轨迹进行关联。

```python
def merge_within_camera(dataset: CameraDataset, max_time_gap_ms=60000, max_y_gap_cm=5000):
    """
    在同一摄像头内合并跨文件窗口的轨迹片段。
    max_time_gap_ms: 窗口间最大允许时间间隙（ms），默认60秒
    max_y_gap_cm: 窗口边界处最大允许y坐标差（cm）
    """
    for window_a, window_b in adjacent_windows(dataset):
        for traj_a in window_a.trajectories:
            if not traj_a.is_multi_node():
                continue
            best_match = None
            best_cost = float('inf')
            end_node = traj_a.last_valid_node()
            for traj_b in window_b.trajectories:
                if not traj_b.is_multi_node():
                    continue
                start_node = traj_b.first_valid_node()
                time_diff = start_node.timestamp - end_node.timestamp
                y_diff = start_node.y - end_node.y
                if time_diff <= 0 or time_diff > max_time_gap_ms:
                    continue
                if abs(y_diff) > max_y_gap_cm:
                    continue
                # 速度一致性和类型一致性检查
                type_match = majority_type(traj_a) == majority_type(traj_b)
                if not type_match:
                    continue
                cost = abs(time_diff - abs(y_diff) / (traj_a.avg_speed_cm_ms or 0.001))
                if cost < best_cost:
                    best_cost = cost
                    best_match = traj_b
            if best_match:
                merge_trajectories(traj_a, best_match)
```

### 3.1 总体思路

基于本数据的特殊优势（统一y坐标 + 同步时间戳），采用 **"空间优先 + 时空联合"** 的策略：

```
六路数据 → 同摄像头跨文件合并 → 按y坐标空间对齐 → 时间约束关联匹配 → 盲区插值补全 → 完整轨迹
```

### 3.2 详细步骤

#### 步骤1：数据解析与统一化

将所有txt文件解析为统一的数据结构：

```python
trajectory = {
    'camera_id': 'TV023',           # 摄像头编号
    'km_marker': 'K615+703',        # 公里桩
    'file_name': 'K615+703TV023_2024-07-25-14-40-19.txt',
    'window_start': datetime(2024,7,25,14,40,19),  # 时间窗口起始
    'nodes': [
        {
            'timestamp': 1721889619088,   # 毫秒时间戳
            'x': 612.91,                   # 像素x坐标
            'y': 61579708.47,              # 世界y坐标（cm）
            'speed': 0.0,                  # 瞬时速度（km/h）
            'acceleration': None,          # 加速度
            'vehicle_type': 'car',         # 车辆类型（本节点标注）
            'is_valid': True               # 是否有效坐标点
        },
        # ... 更多节点
    ],
    'majority_type': 'car',          # 多数投票类型
    'is_static': False,               # 是否为静止轨迹
}
```

解析时的关键处理：
- **(0,0)坐标过滤**：x==0且y==0的节点标记 `is_valid=False`
- **无效节点回退**：获取轨迹首/末节点时，若首/末节点无效，依次向前/后取最近的有效节点
- **多数类型投票**：统计所有节点的vehicle_type，取出现次数最多的作为轨迹代表类型
- **静止检测**：若所有有效节点y坐标标准差 < 100cm且平均速度 < 5km/h，标记为静止轨迹
- **速度null处理**：speed为 `null` 或 `0.000000` 时记录为None，通过相邻点位置差/时间差反算估计速度

#### 步骤2：全局y坐标对齐

| 操作 | 方法 |
|------|------|
| y坐标标准化 | y值无需转换，直接使用（单位cm） |
| 摄像头顺序 | 按y坐标从小到大排序：TV023 → TV024 → TV025 → TV026 → TV027 → TV028 |
| 空间重叠检测 | 相邻摄像头y坐标范围有显著重叠，有利于匹配 |

#### 步骤3：跨摄像头轨迹匹配（核心算法）

采用 **时空约束 + 匈牙利算法** 进行相邻摄像头间的轨迹匹配。

**匹配特征向量**（用于轨迹对）：

| 特征 | 权重 | 说明 |
|------|------|------|
| 时间差 Δt | 高 | 前一摄像头轨迹结束时间 与 后一摄像头轨迹开始时间 之差 |
| y坐标差 Δy | 高 | 前一摄像头轨迹末有效节点y 与 后一摄像头轨迹首有效节点y 之差 |
| 速度一致性 | 中 | 前一摄像头末速度 与 后一摄像头首速度 的差异 |
| 车辆类型一致性 | 中 | 多数投票类型的匹配（car/truck/van/bus/pika/motorbike） |
| x坐标连续性 | 低 | 像素x坐标的过渡（受摄像头角度影响大，降权） |

**匹配算法伪代码**（含预筛选 + 多数投票 + 方阵填充）：

```python
def match_trajectories(cam_a_trajs, cam_b_trajs, 
                        max_time_gap_s=120, max_y_gap_cm=25000):
    """
    cam_a: 前一摄像头（如TV023）
    cam_b: 后一摄像头（如TV024）
    max_time_gap_s: 最大允许时间差（秒）
    max_y_gap_cm: 最大允许位置差（cm），250m缓冲以覆盖大幅FOV
    """
    # Step 0: 过滤候选轨迹
    # 仅使用多节点、非静止轨迹参与匹配
    cam_a_candidates = [t for t in cam_a_trajs 
                        if t.is_multi_node() and not t.is_static]
    cam_b_candidates = [t for t in cam_b_trajs 
                        if t.is_multi_node() and not t.is_static]
    
    # Step 1: 预筛选 —— 快速排除明显不匹配的轨迹对
    candidate_pairs = []
    for i, traj_a in enumerate(cam_a_candidates):
        end_node = traj_a.last_valid_node()
        for j, traj_b in enumerate(cam_b_candidates):
            start_node = traj_b.first_valid_node()
            
            # 时间约束（前轨迹必须早于后轨迹）
            time_diff_ms = start_node.timestamp - end_node.timestamp
            if time_diff_ms <= 0 or time_diff_ms > max_time_gap_s * 1000:
                continue
            # 空间约束（y坐标差在合理范围内）
            y_diff = start_node.y - end_node.y
            if abs(y_diff) > max_y_gap_cm:
                continue
            candidate_pairs.append((i, j, end_node, start_node, traj_a, traj_b))
    
    # Step 2: 构建代价矩阵（矩形 → 填充为方阵）
    n_a = len(cam_a_candidates)
    n_b = len(cam_b_candidates)
    n_max = max(n_a, n_b)
    cost_matrix = [[float('inf')] * n_max for _ in range(n_max)]
    
    for (i, j, end_node, start_node, traj_a, traj_b) in candidate_pairs:
        cost = compute_pair_cost(end_node, start_node, traj_a, traj_b)
        cost_matrix[i][j] = cost
    
    # Step 3: 匈牙利算法求解（scipy.optimize.linear_sum_assignment）
    from scipy.optimize import linear_sum_assignment
    row_ind, col_ind = linear_sum_assignment(cost_matrix)
    
    # Step 4: 过滤低质量匹配（代价超过阈值的视为不匹配）
    MAX_ACCEPTABLE_COST = 5000.0
    matches = []
    for r, c in zip(row_ind, col_ind):
        if r < n_a and c < n_b and cost_matrix[r][c] < MAX_ACCEPTABLE_COST:
            matches.append((cam_a_candidates[r], cam_b_candidates[c], cost_matrix[r][c]))
    
    return matches


def compute_pair_cost(end_node, start_node, traj_a, traj_b):
    """计算两个轨迹间的匹配代价（值越小越匹配）"""
    # 权重配置
    WEIGHT_TIME = 1.0        # 时间差权重
    WEIGHT_POSITION = 1.0    # 位置差权重
    WEIGHT_SPEED = 0.5       # 速度一致性权重
    WEIGHT_TYPE = 10.0       # 类型不匹配惩罚
    PENALTY_TYPE_MISMATCH = 50.0  # 类型不匹配固定惩罚
    
    time_diff_ms = start_node.timestamp - end_node.timestamp
    y_diff = start_node.y - end_node.y
    
    # 时间代价（归一化到秒）
    cost = WEIGHT_TIME * time_diff_ms / 1000.0
    
    # 位置代价（归一化到米，y_diff单位cm）
    cost += WEIGHT_POSITION * abs(y_diff) / 100.0
    
    # 速度一致性代价
    # 转换: km/h → cm/ms: speed / 36.0
    if end_node.speed and end_node.speed > 1.0 and start_node.speed:
        speed_a_cm_ms = end_node.speed / 36.0
        expected_travel_time_ms = abs(y_diff) / max(speed_a_cm_ms, 0.001)
        speed_cost = abs(expected_travel_time_ms - time_diff_ms) / 1000.0
        cost += WEIGHT_SPEED * speed_cost
    
    # 类型一致性代价（多数投票）
    type_a = majority_vote_type(traj_a)
    type_b = majority_vote_type(traj_b)
    if type_a != type_b:
        cost += WEIGHT_TYPE * PENALTY_TYPE_MISMATCH
    
    return cost
```

**关键参数配置**：

| 参数 | 建议值 | 依据 |
|------|--------|------|
| 最大时间间隔 | 120秒 | 隧道最长约650m覆盖，车速30-120km/h时通过时间约20-78秒 |
| 最大y坐标差 | 25000 cm | 相邻摄像头实际FOV跨度可达250m，考虑重叠和盲区后仍有此缓冲 |
| 预筛选时间差 | >0 且 ≤120000ms | 必须正时间差（前后关系）；不超过2分钟 |
| 匈牙利匹配代价上限 | 5000 | 超过此值视为不匹配 |
| 不匹配惩罚 | ∞ (inf) | 填充矩阵的空项 |
| 速度一致性最低速度 | 1.0 km/h | 低于此值视为静止，跳过速度代价计算 |

#### 步骤4：盲区处理与轨迹插值

当两个匹配的轨迹片段之间存在时间和空间间隙时（盲区），需要进行插值补全。

**插值策略**：

| 间隙情况 | 处理方式 |
|----------|----------|
| 时间间隙 < 5秒 | 线性插值（位置、速度） |
| 时间间隙 5-30秒 | 基于末速度的匀速运动插值 |
| 时间间隙 > 30秒 | 标记为低置信度，仍做插值但添加标记 |
| 末速度 > 0 | 使用末速度进行匀速外推 |
| 末速度为None或0 | 使用y坐标差/时间差反算的平均速度 |

```python
def interpolate_gap(end_node, start_node, num_interp_points=10):
    """
    在轨迹片段之间生成插值点。
    speed单位: km/h, y单位: cm
    """
    dt_ms = start_node.timestamp - end_node.timestamp
    dy = start_node.y - end_node.y
    
    # 估算区间速度（km/h）
    if end_node.speed and end_node.speed > 1.0:
        est_speed_kmh = end_node.speed
    else:
        # 通过位置差/时间差反算:
        # cm/ms → m/s: ÷100 × 1000 → km/h: ×3.6
        est_speed_kmh = (dy / dt_ms * 1000 / 100) * 3.6 if dt_ms > 0 else 0
    
    interp_points = []
    for i in range(1, num_interp_points + 1):
        ratio = i / (num_interp_points + 1)
        interp_points.append({
            'timestamp': int(end_node.timestamp + dt_ms * ratio),
            'x': None,  # x坐标在盲区无意义
            'y': end_node.y + dy * ratio,
            'speed': est_speed_kmh,
            'acceleration': None,
            'vehicle_type': end_node.vehicle_type,
            'camera': 'INTERP',
            'interpolated': True
        })
    return interp_points
```

        types = [n.vehicle_type for n in self.nodes if n.is_valid]
        if not types:

        return Counter(types).most_common(1)[0][0]

        for n in self.nodes:
            if n.is_valid:

        return None

## 五、潜在挑战与对策

### 5.1 多车同时段通过

**问题**：同一时间段内多辆车在相邻摄像头间通过，可能导致匹配歧义。

**对策**：
- 利用多数投票车辆类型进行粗粒度过滤
- 利用速度信息约束：前后速度差异过大的匹配赋予高代价
- 匈牙利算法能够处理多对多的全局最优分配
- 设置代价上限过滤低质量匹配

### 5.2 摄像头盲区

**问题**：摄像头间距130m，虽然FOV覆盖范围比预期大（120-250m），但各摄像头的有效检测区域（高置信度区域）可能较小，仍存在盲区。

**对策**：
- 通过匹配结果反推实际盲区范围，动态调整匹配参数
- 盲区内轨迹使用匀速/线性插值
- 对插值节点添加置信度标记（`interpolated=True`）
- 记录每个节点的来源摄像头，便于追溯

### 5.3 轨迹内车辆类型不恒定

**问题**：同一轨迹的不同节点可能被标记为不同类型（如car→truck→car），直接取首/末节点类型会得出错误结论。

**对策**：
- 使用多数投票确定轨迹代表类型
- 在匹配时使用代表类型进行比较
- 记录类型分布统计，便于后期分析检测器性能

### 5.4 静止/振荡轨迹

**问题**：后期摄像头（TV027、TV028）中存在大量静止车辆轨迹，y值在小范围内振荡（如61644260~61644391循环），不应被跨摄像头匹配。

**对策**：
- y坐标标准差 < 100cm 且平均速度 < 5km/h 的轨迹标记为静止
- 静止轨迹从匹配候选集中排除
- 保留静止轨迹数据用于停车行为分析

### 5.5 速度/加速度为null

**问题**：许多轨迹点的速度和加速度字段为null或0，但实际车辆可能在运动。

**对策**：
- 从相邻有效点通过位置差/时间差计算估计速度：`(dy_cm / dt_ms * 1000 / 100) * 3.6` → km/h
- 对估计值添加来源标记（`estimated` vs `measured`）
- 在匹配算法中对仅有估计速度的轨迹适当降权

### 5.6 异常加速度值

**问题**：许多轨迹点的加速度绝对值达到50-100+，远超物理上限（普通乘用车最大约3-5 m/s²）。

**对策**：
- 对 `|acceleration| > 15` 的点标记为噪声，在插值中忽略
- 在匹配代价计算中不使用异常加速度值
- 记录加速度分布统计，辅助评估数据质量

### 5.7 轨迹断裂

**问题**：车辆在某些摄像头下可能未被完整跟踪（如被遮挡），导致轨迹在中途断裂。

**对策**：
- 同一摄像头内先做跨文件合并（Step 0）
- 跨摄像头匹配失败时，轨迹到此终止
- 记录所有未匹配的轨迹片段，便于人工复核

## 六、评估与验证策略

### 6.1 拼接结果质量评估

由于缺少标注的完整轨迹真值（ground truth），需要采用启发式+自洽检验的方式进行评估：

| 评估维度 | 方法 | 可接受标准 |
|----------|------|-----------|
| **匹配成功率** | 匈牙利匹配成功的轨迹对数 / 候选轨迹对数 | >60% |
| **速度连续性** | 拼接后轨迹的速度变化标准差 | <15 km/h |
| **时间合理性** | 相邻摄像头间时间间隔与实际距离/速度的一致性 | 偏差<30% |
| **空间连续性** | y坐标的单调性和平滑性 | 无回退跳跃（Δy>0） |
| **类型一致性** | 匹配对中车辆多数投票类型一致的比例 | >85% |
| **y坐标间隔分布** | 相邻摄像头匹配间隔 Δy 的分布 | 集中在物理间距±50m附近 |

### 6.2 交叉验证方法

1. **正向/反向匹配一致性**：TV023→TV024 与 TV024→TV023 的匹配结果应对称（对称性检验）

2. **链式一致性验证**：对于跨3个以上摄像头的完整轨迹，中间摄像头的轨迹应同时满足与前、后摄像头的时空约束

3. **人工抽样验证**：随机抽取100条拼接轨迹，手动检查时间-空间图表，验证轨迹的物理合理性

4. **统计对比**：对比拼接前后的车辆通过量（每时间窗口的车辆数），应当接近一致（差值<10%）

### 6.3 计算效率优化

匈牙利算法时间复杂度 O(n³)，当单个时间窗口内包含数百条轨迹时可能导致性能瓶颈。

| 策略 | 说明 |
|------|------|
| **时间窗口分组** | 先按30分钟时间窗口分组，仅在相同窗口内的轨迹间进行匹配 |
| **预筛选过滤** | 在构建代价矩阵前，用宽松的时空约束快速排除明显不匹配的轨迹对 |
| **候选集缩减** | 仅使用多节点、非静止的活跃轨迹参与匹配 |
| **并行化** | 5个相邻摄像头对、多个时间窗口均可并行执行 |
| **分批处理** | 若单窗口轨迹数 > 500，按y坐标分段（如每5000cm一段） |

```python
def prefilter_candidates(traj_a, traj_b, max_time_ms=120000, max_y_cm=25000):
    """快速预筛选：排除明显不匹配的轨迹对（仅需首末节点信息）"""
    end_node = traj_a.last_valid_node()
    start_node = traj_b.first_valid_node()
    if not end_node or not start_node:
        return False
    time_diff = start_node.timestamp - end_node.timestamp
    if time_diff <= 0 or time_diff > max_time_ms:
        return False
    y_diff = start_node.y - end_node.y
    if abs(y_diff) > max_y_cm:
        return False
    # 宽松的类型预检
    if traj_a.majority_type != traj_b.majority_type:
        return False
    return True
```

## 十、总结

本数据集具有三个天然优势，极大简化了轨迹拼接任务：

1. **统一世界y坐标系**：六路摄像头的y坐标在同一个全局坐标系中（单位cm），无需进行复杂的相机标定或坐标变换。y坐标随公里桩递增而单调递增，空间对齐直观直接。

2. **同步时间戳**：所有摄像头使用Unix毫秒时间戳，时间已自然同步，无需时间对齐步骤。

3. **显著的摄像头FOV重叠**：各摄像头的实际y坐标检测范围（120-250m）远超最初估计，相邻摄像头间存在显著重叠区域，大大提升了跨摄像头匹配的成功率。

基于以上优势，推荐的核心策略为：

> **"晚期拼接（Late Connection）+ 时空约束 + 匈牙利算法 + 多数投票类型匹配"**

关键改进点（相比初版方案）：

- **y坐标范围数据校准**：基于实际数据统计更新了所有摄像头的y坐标覆盖范围
- **同摄像头跨文件合并**：新增Step 0，处理车辆跨越30分钟时间窗口的情况
- **多数投票车辆类型**：解决单一轨迹内类型不恒定的问题
- **静止/振荡轨迹过滤**：识别并排除停泊车辆的轨迹，避免误匹配
- **预筛选优化**：在构建代价矩阵前用宽松约束快速过滤，显著降低O(n³)复杂度
- **最大y间隔更新**：从15000cm提升到25000cm，匹配实际FOV范围
- **5对摄像头并行匹配**：独立匹配对可完全并行执行

该方法在保证匹配准确性的同时，具有计算效率高、易于实现和调试的优点。
