# 拼接轨迹对齐优化：车道路径吸附

**日期**: 2026-06-01  
**状态**: 已审批

## 1. 背景

当前拼接轨迹回放系统使用全局单一旋转变换（`rotation_diff = map_angle - data_angle + 180°`）将拼接 JSON 节点映射到 CARLA 世界坐标。存在两个问题：

1. **x 坐标归零**：拼接数据的 x 是摄像头像素坐标，变换公式中 `rx = (x - ds[0]) × DATA_SCALE` 因 x 不可比而失效，rx≈0，导致横向偏移归零
2. **单车道聚集**：所有轨迹的路点落在 `TUNNEL_ENTRY` 投影的同一条车道上，车辆无法区分车道

目标：利用拼接数据中可用的 y（世界坐标 cm）和 x（摄像头像素）+ camera_id，将车辆精确分配到对应车道的中心路径上。

## 2. 数据前提

### 2.1 拼接节点字段

| 字段 | 存在性 | 性质 | 可靠性 |
|------|--------|------|--------|
| `y` | 始终存在 | 世界纵坐标 cm，隧道方向单调递增 | 高 |
| `x` | 实测节点存在，插值节点 null | 摄像头像素坐标（同摄像头内可比） | 同摄像头内可靠 |
| `camera_id` | 始终存在 | 来源摄像头标识（TV023-TV028） | 高 |
| `speed` | 大多存在 | km/h | 中 |
| `timestamp` | 始终存在 | Unix ms | 高 |

### 2.2 隧道结构

三车道隧道，车道 ID -1（左/快）、-2（中/巡航）、-3（右/慢），车道宽度 3.5m，总宽度约 10.5m。

车道路径可通过 `tp_tunnel_traffic/lane_sampling.py` 的 `build_three_lane_paths()` 从 XODR 地图提取，返回各车道中心路径的 CARLA Transform 序列。

## 3. 设计

### 3.1 整体架构

```
Phase 1: 启动时
  从 XODR 提取三车道中心路径（{-1: [Transform], -2: [Transform], -3: [Transform]}）

Phase 2: 加载轨迹时
  按 camera_id 分组，对每个摄像头的实测节点 x 值做三分位聚类
  → 建立 x → 车道号映射函数

Phase 3: 逐节点构建路点时
  ┌─ 实测节点 ──→ 根据 x + camera_id 确定车道
  │              在对应车道路径上取最近路点
  │
  └─ 插值节点 ──→ 用前后实测节点车道信息，沿该车道路径线性插值
```

### 3.2 模块分工

| 模块 | 变更 | 职责 |
|------|------|------|
| `tp_tunnel_traffic/lane_sampling.py` | 复用 | `build_three_lane_paths(carla, xodr_path)` 提取车道中心路径 |
| `tp_replay/main.py: _run_stitch_kinematic` | 修改 Phase 3 | x→车道聚类 + 车道路径吸附 |
| `tp_replay/main.py: _run_stitch_simple` | 修改 Phase 3 | 同上 |
| `tp_replay/engine.py` | 不改 | 坐标变换参数仍由 process_data() 计算，y 轴纵向变换保留 |
| `tp_replay/config.py` | 不改 | — |

### 3.3 x→车道聚类算法

```
对每个摄像头 camera_id:
  收集该摄像头下所有实测节点的 x 值
  排序，取 1/3 和 2/3 分位点

  ┌────────────┬────────────┬────────────┐
  │ x < tercile1 │ tercile1 ≤ x < tercile2 │ x ≥ tercile2 │
  │ 车道 -1      │ 车道 -2                 │ 车道 -3     │
  └────────────┴────────────┴────────────┘
```

聚类在加载 JSON 后、构建 wpts 前执行一次，6 个摄像头各自独立聚类。

### 3.4 路点吸附到车道路径

```
节点: {x=350, y=61580000(cm), speed=60(km/h), camera_id="TV023"}

1. 保留原纵向变换：对节点 y(cm) 做旋转+缩放+平移 → 得到 CARLA 世界 rough_loc
2. x=350 查 TV023 映射表 → 目标车道 = -1
3. 在车道路径[-1]（已按世界 Y 排序）中，用 rough_loc.y 二分查找最近路点
4. world_loc = 该路点的 Transform（X/Y/Z 已在车道表面上）
5. wpt = (world_loc, 60 km/h, timestamp)
```

**关键**：纵向变换（y→CARLA）保留现有逻辑不变，仅横向定位从"rx≈0 旋转"改为"车道路径查表"。

### 3.5 插值节点处理

插值节点（`x=null`）的车道指派：

```
取前后最近两个实测节点，如果它们在同一车道 → 插值节点也用该车道
如果不在同一车道 → 取前一个实测节点的车道（保守策略）
```

沿目标车道路径，在前后实测节点的路点之间线性插值得到插值节点的位置和速度。

## 4. 数据流

```
stitched_trajectories.json
    │
    ▼
加载 & 过滤 (quality/camera_count/track_limit/time_window)
    │
    ▼
x→车道聚类 (按 camera_id 分组，计算分位点)
    │
    ▼
逐节点路点构建:
    ├─ 实测节点: x→车道 → 车道路径查表 → world_loc
    └─ 插值节点: 前后实测节点车道 → 车道路径线性插值 → world_loc
    │
    ▼
PID 路点跟随自动驾驶 (不变)
```

## 5. 与当前方案的对比

| | 当前 | 优化后 |
|------|------|--------|
| 横向定位 | `rx=(x-ds[0])×0.01`→rx≈0，旋转后落在同一条线上 | x→车道聚类 + 车道路径查表 |
| 纵向定位 | y→CARLA 旋转平移 | 同上，不变 |
| 路点吸附 | `get_waypoint(project_to_road)` | 车道路径查表（自带正确 X/Y/Z） |
| 车道分配 | 无（全挤一道） | 逐节点分配（0/1 级） |
| 变道支持 | 无 | 逐节点 camera_id/x 变化，自然变道 |
| PID 自动驾驶 | 不变 | 不变 |

## 6. 已知限制

1. **同摄像头内变道不可检测**：x 是像素坐标无标定参数，无法判断画面内 x 变化是"变道"还是"正常行驶"。车辆在同摄像头内始终走在同一车道。
2. **车道聚类精度**：三分位是粗粒度方法，假设车辆在三个车道上均匀分布。如果实际分布不均匀（如某车道车流很少），聚类会有偏差。
3. **摄像头交界处**：相邻摄像头之间 y 坐标有重叠，节点可能落在两个摄像头的边界。使用 camera_id 字段直接确定车道，不依赖 y 区间匹配。

## 7. 未纳入的范围

- 摄像头标定（像素→世界坐标映射矩阵）
- 车道内横向偏移（亚车道级精度）
- 碰撞避免
