## 一、背景与目标

### 1.1 背景

本项目包含两大子系统：

- **轨迹拼接系统**（`trace_data/track24.7.25-24.8.5_79_6lu/docs/轨迹拼接方案报告.md`）：将六路隧道摄像头的车辆轨迹片段拼接为完整的跨摄像头轨迹，输出 JSON 格式的 `stitched_trajectories`。
- **轨迹复现引擎**（`tp_replay/`）：将外部轨迹数据在 CARLA 仿真世界中回放，支持 kinematic 和 physics_follow 两种控制模式。

当前这两个系统之间存在**格式断层**：拼接后的 JSON 数据无法直接喂入 `tp_replay` 引擎。

### 1.2 目标

设计并实现一个**拼接轨迹数据适配器**（`StitchAdapter`），将拼接系统的 JSON 输出转换为 `tp_replay` 引擎可消费的 `VehicleTrack` 列表，实现从"原始摄像头轨迹 → 拼接 → CARLA 回放"的完整闭环。

### 1.3 关键约束

| 约束 | 说明 |
|------|------|
| 最小侵入 | 不修改 `engine.py` 的核心回放逻辑，仅在数据输入层做适配 |
| 坐标兼容 | 拼接后的 y 坐标（世界cm）与原始数据一致，复用现有坐标对齐参数 |
| 质量可控 | 支持按 `quality_score`、`camera_count` 等过滤低质量拼接轨迹 |
| 插值处理 | 拼接产生的插值节点（x=null）需合理映射到 CARLA 坐标 |

## 二、拼接轨迹数据格式（输入侧）

### 2.1 JSON Schema

  "camera_count": 6,
  "total_covered_y_cm": 62035.0,
  "interp_ratio": 0.08,
  "quality_score": 0.92,
  "nodes": [
    {
      "timestamp": 1721889619088,
      "x": 612.91,
      "y": 61579708.47,
      "speed": 0.0,
      "acc": null,
      "type": "car",
      "camera": "TV023",

    },
    {
      "timestamp": 1721889710000,
      "x": null,
      "y": 61582643.21,
      "speed": 52.6,
      "acc": null,
      "type": "car",
      "camera": "INTERP",
      "interpolated": true
    }

    ["TV024", "TV025", 89.2]
  ]

### 2.2 与原始数据的差异

| 维度 | 原始摄像头数据 | 拼接后数据 |
|------|---------------|-----------|
| 存储格式 | 每行一个轨迹片段（txt） | 每个完整轨迹一个 JSON 对象 |
| 坐标系 | 各摄像头独立世界坐标(cm) | 统一世界坐标(cm)，跨摄像头连续 |
| 覆盖率 | 单摄像头 120-250m | 跨 2-6 个摄像头，最长 ~620m |
| 特殊节点 | (0,0) 为跟踪丢失 | 插值节点：x=null, camera="INTERP" |
| 元数据 | 无 | quality_score, camera_count, matched_pairs |
| 轨迹数量 | ~3186 文件 × ~100 行/文件 | 约 3000-10000 条完整轨迹 |

## 三、tp_replay 现有数据管道分析

### 3.1 数据消费入口

```python
# engine.py:164 — process_data(file_path)
def process_data(self, file_path):
    # 1) 读取文本文件 → 按行分割
    lines = f.readlines()

    # 2) 自动锚点选择（扫描前120行，选最优对齐参数）
    #    输出: data_start_point, data_angle

    # 3) 全局时间 rebase（min_ts → 0）
    #    输出: global_start_time_raw

    # 4) 逐行解析 → VehicleTrack 列表
    #    每6个token一组节点 → 坐标对齐变换 → TrackFrame
```

### 3.2 坐标对齐变换链

```
# engine.py:381-387
rx = (x - data_start_point[0]) * DATA_SCALE          # 平移 + 缩放
ry = (y - data_start_point[1]) * DATA_SCALE * SCALE_Y
rot_x = rx * cos_a - ry * sin_a                       # 旋转（map_angle - data_angle）
rot_y = rx * sin_a + ry * cos_a
final_x = rot_x + TUNNEL_ENTRY_X + off_x              # 平移到 CARLA 锚点
final_y = rot_y + TUNNEL_ENTRY_Y + off_y
rough_loc = carla.Location(final_x, final_y, TUNNEL_ENTRY_Z)
```

**关键参数**（来自 `config.py`）：

| 参数 | 值 | 来源 |
|------|-----|------|
| `DATA_SCALE` | 0.01 | cm → m 转换 |
| `YAW_CORRECTION` | 动态计算 | `map_angle - data_angle` |
| `TUNNEL_ENTRY` | (-2135.49, 556.03, 1.00) | CARLA 世界锚点 |
| `REVERSE_DIRECTION` | True | 隧道逆向 |
| `SPEED_FACTOR` | 1/3.6 | km/h → m/s |

### 3.3 VehicleTrack 模型

```python
class VehicleTrack:
    id: str
    type_str: str       # 车辆类型（多数投票）
    frames: [TrackFrame] # 按时间排序的帧列表
    actor: Vehicle       # CARLA actor（spawn 后赋值）
    start_time: float    # 相对时间（秒），rebase 后
    end_time: float
```

### 3.4 适配切入点

最优切入点是：**绕过 `process_data()` 的文本解析逻辑，在已有坐标对齐参数和地图锚点已就绪的前提下，直接将拼接 JSON 数据转换为 `VehicleTrack` 列表，注入到 `engine.pending_tracks`**。

具体来说，适配器需要：
1. 读取拼接 JSON → 解析 `stitched_trajectories`
2. 按 `quality_score` / `camera_count` 过滤
3. 对每条轨迹的节点列表执行与 `process_data()` 相同的坐标变换
4. 处理插值节点（x=null → 仅用 y 坐标定位）
5. 构建 `TrackFrame` → `VehicleTrack` 列表
6. 设置 `global_start_time_raw` 用于时间 rebase

## 四、适配方案设计

### 4.1 方案对比与选择

| 维度 | 方案 A：文本转换 | 方案 B：直接适配器（推荐） |
|------|-----------------|--------------------------|
| 思路 | 将拼接 JSON 转回 txt 格式，复用 `process_data()` | 新建 `StitchAdapter` 类，直接构建 `VehicleTrack` |
| 侵入性 | 零侵入（不改 engine） | 在 `main.py` 增加一条分支 |
| 代码量 | 少（~50行转换函数） | 中（~200行独立类） |
| 灵活性 | 低（受限于 txt 格式） | 高（支持过滤、元数据保留） |
| 插值处理 | 困难（x=null 无法写入 txt） | 灵活（直接注入合理默认值） |
| 元数据利用 | 无法利用 quality_score 等 | 可按质量/摄像头数过滤 |

**推荐方案 B**：直接适配器方式，原因：
- 拼接数据包含了 txt 格式无法表达的元数据（quality_score、matched_pairs）
- 插值节点的 x=null 需要特殊处理，文本转换会丢失信息
- 未来可能需要按质量分级回放、选择性展示特定摄像头来源的节点

### 4.2 数据流架构

```
┌──────────────────────┐
│  stitched_traj.json  │  ← 拼接引擎输出
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│   StitchAdapter      │  ← 新增模块 (tp_replay/stitch_adapter.py)
│                      │
│ 1. load_json()       │     解析 JSON，提取轨迹列表
│ 2. filter_tracks()   │     按 quality_score / camera_count 过滤
│ 3. transform_nodes() │     坐标对齐变换（复用 engine 参数）

└──────────┬───────────┘

│   .pending_tracks    │     注入 VehicleTrack 列表
│   .tick(fixed_dt)    │     正常回放
└──────────────────────┘
```

### 4.4 插值节点坐标处理策略

拼接轨迹中的插值节点 `x=null`，在 CARLA 中需要指定一个合理的世界坐标。

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| **y-only 定位** | x = data_start_point[0]（保持在锚点x位置），仅通过 y 坐标确定隧道纵向位置 | 隧道是直线，x 变化小 |
| **邻点内插** | 取前后最近非插值节点的 x 做线性内插 | x 变化显著的弯曲路段 |
| **车道中心** | 不使用 x，直接用 y 坐标在 CARLA 地图上 project_to_road 找车道中心 | 最精确，但需要地图查询 |

**推荐策略**：默认使用 **y-only 定位**（隧道近似直线，x 偏差影响小），配以 `project_to_road` 吸附到最近车道。若需要更高精度，可在 `StitchAdapter` 中配置为车道中心模式。

```python
def _node_to_frame(self, node, data_start, cos_a, sin_a):
    x = node.get("x")
    y = node["y"]

    # 插值节点：y-only 定位
    if x is None or abs(float(x)) < 1.0:
        x = data_start[0]  # 使用锚点 x，由车道吸附纠正

    # 标准坐标变换（与 engine.py:381-387 完全一致）
    rx = (x - data_start[0]) * config.DATA_SCALE
    ry = (y - data_start[1]) * config.DATA_SCALE * config.SCALE_Y
    rot_x = rx * cos_a - ry * sin_a
    rot_y = rx * sin_a + ry * cos_a
    final_x = rot_x + self.engine.entry_loc.x
    final_y = rot_y + self.engine.entry_loc.y

    rough_loc = carla.Location(final_x, final_y, self.engine.entry_loc.z)

    # 车道吸附
    wp = self.engine.map.get_waypoint(rough_loc, project_to_road=True,
                                       lane_type=carla.LaneType.Driving)
    if wp:
        final_loc = wp.transform.location
        final_rot = wp.transform.rotation
    else:
        final_loc = rough_loc
        final_rot = carla.Rotation()

    # 速度转换：km/h → m/s
    speed_raw = node.get("speed")
    v_mps = float(speed_raw) * config.SPEED_FACTOR if speed_raw else 0.0

    return TrackFrame(ts=rel_time, loc=final_loc, rot=final_rot, v=v_mps)
```

### 4.5 时间处理

拼接后的时间戳是绝对 Unix 毫秒，需要 rebase 为相对时间：

```python
def _rebase_time(self, tracks: List[dict]) -> float:
    """找到全局最早时间戳，用于 rebase"""
    global_min_ts = float("inf")
    for t in tracks:
        for node in t["nodes"]:
            ts = node.get("timestamp", float("inf"))
            if ts < global_min_ts:
                global_min_ts = ts
    return global_min_ts  # 毫秒

# 在 convert 时：
rel_time = (node["timestamp"] - global_min_ts) / 1000.0  # → 秒
```

### 5.2 StitchAdapter 核心实现

```python
"""tp_replay 拼接轨迹适配器。

将拼接引擎输出的 stitched JSON 转换为 ReplayEngine 可消费的 VehicleTrack 列表。
"""

from __future__ import annotations

import json
import logging
import math
from typing import List, Optional, Tuple

from . import config
from .carla_compat import require_carla
from .models import TrackFrame, VehicleTrack

logger = logging.getLogger(__name__)


class StitchAdapter:
    """拼接轨迹数据 → VehicleTrack 适配器"""

    def __init__(self, engine):
        """engine: 已初始化的 ReplayEngine 实例"""
        self.engine = engine
        self.carla = require_carla()

    # ── 公开接口 ──────────────────────────────────────────

    def load_and_convert(
        self,
        json_path: str,
        min_quality: float = 0.5,
        min_cameras: int = 2,
        max_tracks: Optional[int] = None,
    ) -> List[VehicleTrack]:
        """
        主入口：加载拼接 JSON → 过滤 → 坐标变换 → VehicleTrack 列表。

        参数:
            json_path:   拼接 JSON 文件路径
            min_quality: 最低质量评分（0-1），低于此值的轨迹被过滤
            min_cameras: 最少涉及的摄像头数，单摄像头轨迹过滤
            max_tracks:  最大轨迹数限制（None=不限制）
        返回:
            VehicleTrack 列表，可直接赋值给 engine.pending_tracks
        """
        raw_tracks = self._load_json(json_path)
        logger.info("Loaded %d stitched trajectories from %s", len(raw_tracks), json_path)

        filtered = self._filter_tracks(raw_tracks, min_quality, min_cameras, max_tracks)
        logger.info(
            "Filtered: %d/%d tracks (min_quality=%.2f min_cameras=%d max=%s)",
            len(filtered), len(raw_tracks), min_quality, min_cameras,
            str(max_tracks) if max_tracks else "unlimited",
        )

        global_min_ts = self._find_global_min_ts(filtered)
        self.engine.global_start_time_raw = global_min_ts
        logger.info("Global min timestamp: %.3f ms", global_min_ts)

        # 复用 engine 已计算的坐标变换参数
        cos_a, sin_a = self._get_transform_params()

        vehicle_tracks = []
        for i, st in enumerate(filtered):
            vt = self._stitched_to_vehicle_track(
                st, i, global_min_ts, cos_a, sin_a,
            )
            if vt and vt.frames:
                vehicle_tracks.append(vt)

        logger.info(
            "Converted %d VehicleTracks (total frames=%d)",
            len(vehicle_tracks),
            sum(len(vt.frames) for vt in vehicle_tracks),
        )
        return vehicle_tracks

    # ── 内部方法 ──────────────────────────────────────────

    def _load_json(self, json_path: str) -> List[dict]:
        with open(json_path, "r", encoding="utf-8") as f:
            data = json.load(f)

        # 支持两种 JSON 结构：直接的列表 或 包裹在 key 下
        if isinstance(data, list):
            return data
        if isinstance(data, dict):
            for key in ("trajectories", "stitched_trajectories", "data"):
                if key in data:
                    return data[key]
            # 可能是单个轨迹对象
            return [data]
        return []

    def _filter_tracks(
        self,
        tracks: List[dict],
        min_quality: float,
        min_cameras: int,
        max_tracks: Optional[int],
    ) -> List[dict]:
        result = []
        for t in tracks:
            qs = t.get("quality_score", 1.0)
            cc = t.get("camera_count", 1)
            if qs < min_quality:
                continue
            if cc < min_cameras:
                continue
            result.append(t)
            if max_tracks and len(result) >= max_tracks:
                break
        return result

    def _find_global_min_ts(self, tracks: List[dict]) -> float:
        min_ts = float("inf")
        for t in tracks:
            for node in t.get("nodes", []):
                ts = node.get("timestamp")
                if ts and ts < min_ts:
                    min_ts = ts
        if math.isinf(min_ts):
            return 0.0
        return float(min_ts)

    def _get_transform_params(self) -> Tuple[float, float]:
        """获取 engine 已计算的旋转变换参数 + 横向偏移。

        复用 engine.py 中 process_data() 的旋转矩阵和横向偏移。
        要求 engine 已通过 process_data 或 _cache_transform_params 缓存了参数。
        """
        if hasattr(self.engine, "_stitch_cos_a"):
            self._off_x = getattr(self.engine, "_stitch_off_x", 0.0)
            self._off_y = getattr(self.engine, "_stitch_off_y", 0.0)
            return self.engine._stitch_cos_a, self.engine._stitch_sin_a

        # Fallback: 无缓存时使用恒等变换（需 process_data 先运行）
        self._off_x = 0.0
        self._off_y = 0.0
        logger.warning("No cached transform params on engine; using identity transform")
        return 1.0, 0.0

    def _stitched_to_vehicle_track(
        self,
        st: dict,
        track_id: int,
        global_min_ts: float,
        cos_a: float,
        sin_a: float,
    ) -> Optional[VehicleTrack]:
        """单条拼接轨迹 → VehicleTrack"""
        vtype = st.get("vehicle_type", "car")
        track = VehicleTrack(vehicle_id=f"stitch_{track_id}", type_str=vtype)
        track.camera_count = st.get("camera_count", 0)
        track.quality_score = st.get("quality_score", 0.0)

        nodes = st.get("nodes", [])
        if len(nodes) < 2:
            return None

        data_start = self._get_data_start_point()
        last_valid_v = 0.0

        for node in nodes:
            ts = node.get("timestamp")
            if ts is None:
                continue

            # 时间 rebase: 绝对 ms → 相对秒
            rel_time = (float(ts) - global_min_ts) / 1000.0

            # x 坐标处理：插值节点使用 data_start x
            x_raw = node.get("x")
            if x_raw is None or abs(float(x_raw)) < 1.0:
                x_raw = data_start[0]

            y_raw = node.get("y", 0.0)

            # 坐标变换（与 engine.py:381-387 一致）
            rx = (float(x_raw) - data_start[0]) * float(config.DATA_SCALE)
            ry = (float(y_raw) - data_start[1]) * float(config.DATA_SCALE) * float(config.SCALE_Y)
            rot_x = rx * cos_a - ry * sin_a
            rot_y = rx * sin_a + ry * cos_a
            final_x = rot_x + self.engine.entry_loc.x + self._off_x
            final_y = rot_y + self.engine.entry_loc.y + self._off_y

            rough_loc = self.carla.Location(
                final_x, final_y, self.engine.entry_loc.z
            )

            # 车道吸附
            try:
                wp = self.engine.map.get_waypoint(
                    rough_loc,
                    project_to_road=True,
                    lane_type=self.carla.LaneType.Driving,
                )
                if wp:
                    final_loc = wp.transform.location
                    final_rot = wp.transform.rotation
                else:
                    final_loc = rough_loc
                    final_rot = self.carla.Rotation()
            except Exception:
                final_loc = rough_loc
                final_rot = self.carla.Rotation()

            # 速度转换：km/h → m/s
            speed_raw = node.get("speed")
            if speed_raw is not None:
                try:
                    v_mps = float(speed_raw) * float(config.SPEED_FACTOR)
                    last_valid_v = v_mps
                except (ValueError, TypeError):
                    v_mps = last_valid_v
            else:
                v_mps = last_valid_v

            frame = TrackFrame(ts=rel_time, loc=final_loc, rot=final_rot, v=v_mps)
            track.add_frame(frame)

        if track.frames:
            track.sort_frames()
            # 设置 spawn 时间 = 首帧时间（engine 的 spawn 循环依赖此字段）
            track.next_spawn_time = track.frames[0].ts
        return track

    def _get_data_start_point(self) -> Tuple[float, float]:
        """获取数据锚点坐标。

        优先从 engine 获取已计算的 data_start_point；
        若未计算，使用 config 中的隧道入口锚点反算。
        """
        if hasattr(self.engine, "_data_start_point"):
            return self.engine._data_start_point

        # Fallback: 从 config 锚点反推（精度较低但可用）
        return (0.0, 0.0)
```

### 5.3 引擎集成（main.py 修改）

在 `tp_replay/main.py` 的 `main()` 函数中增加拼接模式分支：

```python
# 在 engine = ReplayEngine(client, config.XODR_PATH) 之后

stitch_json = os.getenv("TP_STITCH_JSON_PATH", "")
if stitch_json:
    from .stitch_adapter import StitchAdapter

    # 先用原始数据跑一次 process_data 以获取坐标对齐参数
    if config.DATA_FILE_PATH and os.path.exists(config.DATA_FILE_PATH):
        engine.process_data(config.DATA_FILE_PATH)
        # process_data 内部已将变换参数缓存到 engine 上（见 5.4 节）
        engine.pending_tracks = []     # 清空原始数据轨迹
    else:
        logger.warning("No anchor data file; stitch adapter may use identity transform")

    adapter = StitchAdapter(engine)
    engine.pending_tracks = adapter.load_and_convert(
        stitch_json,
        min_quality=_get_float_from_env("TP_STITCH_MIN_QUALITY", 0.5),
        min_cameras=_get_int_from_env("TP_STITCH_MIN_CAMERAS", 2),
        max_tracks=_get_int_from_env("TP_TRACK_LIMIT", 0) or None,
    )
else:
    # 原有逻辑：解析原始 txt 数据
    engine.process_data(config.DATA_FILE_PATH)
```

self._data_start_point = data_start_point

## 八、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 拼接质量低下导致回放异常 | 车辆跳跃、漂移 | 设置 `min_quality` 阈值过滤；提供质量分布统计 |
| 坐标对齐参数丢失 | adapter 无法运行 | 缓存参数到 engine；提供 config 预设值 fallback |
| 插值节点 x 坐标不准确 | 车辆短暂偏航 | project_to_road 吸附纠正 + 标注 interpolated 来源 |
| 大规模轨迹导致性能瓶颈 | 回放卡顿 | 使用 `TP_TRACK_LIMIT` + `TP_SELECT_MODE` 筛选 |
| 拼接 JSON 格式变更 | adapter 解析失败 | 错误处理 + 日志 + JSON schema 版本标识 |

### 8.1 回退方案

若 adapter 出问题，可通过以下方式快速回退到原始模式：

## 十、总结

本方案通过设计 `StitchAdapter` 适配器类，在不修改 `tp_replay` 核心回放逻辑的前提下，实现了拼接轨迹数据到 CARLA 回放引擎的无缝对接。

**核心设计决策**：

| 决策 | 选择 | 理由 |
|------|------|------|
| 集成方式 | 新建 adapter 类，在 main.py 分支 | 最小侵入，保持向后兼容 |
| 坐标对齐 | 复用 process_data 的锚点参数 | 避免重复实现对齐算法 |
| 插值节点 | y-only 定位 + project_to_road | 隧道近似直线，吸附纠正即可 |
| 质量过滤 | 通过 env 变量控制阈值 | 灵活可调，不硬编码 |

**新增文件**：`tp_replay/stitch_adapter.py`（~200 行）
**修改文件**：`tp_replay/main.py`（+12 行分支）、`tp_replay/engine.py`（+6 行参数缓存）
**新增环境变量**：`TP_STITCH_JSON_PATH`、`TP_STITCH_MIN_QUALITY`、`TP_STITCH_MIN_CAMERAS`
